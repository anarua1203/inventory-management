Architecture overview

Factory Inventory Management System

A demo dashboard with two tiers. A Vue 3 single-page app calls a FastAPI service, which serves read-only data. That data is loaded from JSON files into memory at startup. There is no database, no authentication and no build-time coupling between the tiers. They talk only through JSON over HTTP.

Data flow: changing a filter

This is the main interaction loop. Here it's traced for the Dashboard, the view that uses every filter.

Client · FilterBar.vue

User picks a filter

The select binds with v-model to one of four refs in useFilters: selectedPeriod, selectedLocation, selectedCategory or selectedStatus. The refs are module-level, so every view shares the same filter state.

Client · Dashboard.vue

A watcher fires and loads data

watch([selectedPeriod, selectedLocation, ...]) calls loadData(). getCurrentFilters() renames the UI refs into API names: Location becomes warehouse and Period becomes month.

Client · api.js

Parallel requests

Promise.all sends /dashboard/summary, /orders, /inventory and /backlog. Each helper leaves out any param whose value is "all".

Server · main.py

Filter in memory

apply_filters() matches warehouse exactly and category/status case-insensitively. filter_by_month() does a substring match on order_date and expands Q1-2025-style values through QUARTER_MAP.

Data · mock_data lists

Read the shared lists

Filtering builds new lists with list comprehensions. The source lists loaded at import stay untouched, so every request starts from the full dataset.

Server · Pydantic

Aggregate, validate, serialize

The summary endpoint computes inventory value, low-stock count and pending orders. List endpoints go through response_model before being returned as JSON.

Client · computed()

Derive and render

Responses land in raw refs (allOrders, inventoryItems, allBacklogItems). Computed properties build status counts, category bars, trend lines and top products. They also filter backlog client-side by the SKUs of the filtered inventory. The SVG charts then re-render.

Data model

These records are defined by Pydantic classes in main.py. The Spending and Reports endpoints return plain dicts without a response model.

InventoryItem inventory.json

  • id, sku, name, category, warehouse
  • quantity_on_hand, reorder_point → low stock when on-hand ≤ reorder
  • unit_cost, location, last_updated

Order orders.json

  • id, order_number, customer, status
  • items: List[dict] (SKU line items)
  • order_date, expected_delivery, actual_delivery?
  • total_value, warehouse?, category?

DemandForecast demand_forecasts.json

  • item_sku, item_name, period, trend
  • current_demand, forecasted_demand

BacklogItem · PurchaseOrder backlog_items.json

  • order_id, item_sku, quantity_needed/available
  • days_delayed, priority
  • has_purchase_order is computed by joining against purchase_orders.json on backlog_item_id. That file is currently empty.

Findings

Each of these was checked against the code and the running server.

Client calls routes that don't exist

  • /api/tasks (GET/POST/PATCH/DELETE) and /api/purchase-orders return 404.
  • App.vue catches the error and logs it to the console. The Tasks modal still shows the four mock tasks from useAuth, but tasks added through the UI fail silently.

Inconsistent client wiring

  • Reports.vue skips api.js and hard-codes http://localhost:8001 in its own axios calls.
  • views/Backlog.vue exists but has no route, so it can't be reached.
  • The API base URL is hard-coded, and there's no Vite proxy or environment variable.

Demo-only by design

  • There is no authentication; the user profile is a hard-coded mock. CORS allows all origins.
  • Data is read-only and in memory. Nothing persists, and changes to the JSON files need a restart.
  • QUARTER_MAP and the report rollups only know about 2025.

Filtering subtleties

  • Inventory has no time dimension, so Period and Status don't affect inventory numbers.
  • total_backlog_items in the summary ignores filters; the Dashboard filters backlog itself.
  • Spending endpoints take no params; the Spending view filters by period in the browser.
